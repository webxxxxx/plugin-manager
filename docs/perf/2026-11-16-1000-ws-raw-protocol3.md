# Protocol 3 raw：20 插件 × 50 WebSocket 512 KiB 连续 60 秒

日期：2026-11-16  
平台：WSL2 Debian Linux x86_64  
构建：`cargo build --release`，默认 `MEM_LEVEL=high`  
连接：20 个 WebUI 插件，每个 50 条 WebSocket，共 **1000 条**  
数据：每条 WS 连续发送 512 KiB binary frame，经插件原样 echo

## protocol 3 格式

插件 stdin/stdout 使用 8 字节头：

```text
u32 payload_len (big endian)
u32 stream_id   (big endian)
payload
```

- `stream_id` 由 daemon 为每条 UI WebSocket 分配；
- 插件必须原样回传 `stream_id`；
- daemon 收到响应后释放 in-flight 预算；
- plugin 声明 `protocol: 3`、`exec.ready: exec`、不能声明 JSON-RPC capabilities；
- UI raw 路由：`/plugin-ui/{id}/{token}/raw`，只接受 binary frame。

每个插件有一个 writer 线程和一个 reader 线程，HTTP reactor 仍然只有 10 条基础线程；
20 个 raw 插件额外带来 40 条 raw I/O 线程。

## 日志检查

`data.log` 63 行，daemon stderr / `svcd.log` 没有：

```text
panic
overflow
fatal runtime
aborted
stack overflow
```

但结束状态不是全绿：

```text
requests_completed = 21466
data_ok            = 21464
errors             = 58
ws_open            = 940
```

也就是说：

- 功能正确性：已完成的 21464 条数据全部原样返回；
- 还有 2 条响应校验失败，58 条连接错误，60 条连接在测试结束时已关闭；
- 这不是可生产的完成状态，必须继续做 raw 背压/错误处理。

## 当前结论

- protocol 3 raw 已经打通：插件 stdin/stdout raw framing、UI `/raw` 路由、stream id 映射、全局预算、插件 echo 都工作。
- 单连接 47/47 正确，1000 连接高负载下仍有 58 个连接错误。
- Windows 的 raw `/raw` 路由尚未实现；当前 raw 生产路径是 Unix。
- 下一步要定位并消除 58 个错误，做到 `ws_open=1000`、`errors=0`，才能按生产标准交付。
