# 20 插件 × 50 WebSocket：1 分钟连续数据传输压测

日期：2026-11-16  
平台：WSL2 Debian Linux x86_64  
构建：`cargo build --release`，默认 `MEM_LEVEL=high`  
连接：20 个 WebUI 插件，每个 50 条 WebSocket，共 **1000 条**  
数据：每条 WS 在 60 秒内发送 **1 MiB** 文本数据，总计 **1000 MiB**

## 配置

```text
max_connections = 4096
max_connections_per_ip = 4096
max_streams = 4096
max_subscriptions = 2048
max_subscribers_per_plugin = 64
http_idle_timeout_secs = 300
```

插件 payload 为 `exec tail -f /dev/null`，无 `sleep`、无子进程。  
客户端使用单线程 `selectors` 事件循环维护 1000 条连接和心跳。

## 日志检查

客户端每秒写一行数据日志，共 61 行（1 行头 + 60 个采样）：

```text
t=01 open=1000 sent_mb=33.33 recv_mb=0.09 errors=0
t=02 open=1000 sent_mb=50.00 recv_mb=0.19 errors=0
...
t=58 open=1000 sent_mb=983.37 recv_mb=5.48 errors=0
t=59 open=1000 sent_mb=1000.00 recv_mb=5.57 errors=0
t=60 open=1000 sent_mb=1000.00 recv_mb=5.67 errors=0
```

检查结果：

- 61 行数据日志全部为 `open=1000`、`errors=0`；
- daemon stderr / svcd.log 没有 `panic`、`overflow`、`fatal`、`abort`、`too large`、`reset` 等错误；
- 结束时 1000 条 WS 全部仍然打开；
- 客户端错误计数为 0。

## 解读

- 1000 条连接、每条 1 MiB，共 1,048,576,000 字节，在 60 秒窗口内全部发送完成。
- 应用层数据吞吐约 **16.67 MB/s**，约 **139.8 Mbit/s**。
- daemon 单核 CPU 约 **83.84%**，瓶颈在 WS 文本解析/JSON-RPC 错误回包；
  插件进程 CPU 接近 0，因为数据是发往 UI 桥的文本帧，不是插件业务处理。
- daemon RSS 从 idle 1000 连接的约 27 MB 上升到约 **49 MB**；
  总 RSS 约 **86 MB**。
- daemon 线程数仍为 **10**，1000 条连接没有变成每连接一条线程。
- 收到的 5.67 MB 是服务端对非 JSON 文本帧返回的 JSON-RPC 错误响应；
  如果要测插件业务 echo 吞吐，需要换成 protocol=1/2 的 echo 插件。
- 本测试每条连接总共 1 MiB，分 60 次发送，属于“连续 1 分钟数据传输”；
  不是每条连接每秒无限发送。
