# 内存预算矩阵：Win11 / WSL2 × 三档 × 三并发

日期：2026-11-21  
平台：Windows x86_64（Win11）+ WSL2 Debian x86_64  
构建：`cargo build --release`；含 2026-11-21 的显式预算修订（`mem_budget_bytes` 写多少就是多少）  
矩阵：2 平台 × 3 档位 × 3 并发 = **18 格**；每格 10 个 `.spk`、60 秒、五面全功能

## 方法

- 每格启动一个全新的 `svcd`，`svcd.conf` 写 `mem_budget_bytes` 与测试口令，`workload` 保持派生。
- 10 个 `.spk` 走 `POST /api/v1/plugins` 安装、逐插件启动；每个插件都被驱动
  invoke（MCP `tools/call`）/ SSE / WebSocket / blob upload / blob download。
- 并发按「每插件」计：`c=1` → 10 个 worker；`c=50` → 500；`c=100` → 1000。
  每个 worker 固定在一个插件上轮转五面，`think=20ms`。
- 每 2 秒采样 daemon 与进程树 RSS/CPU/线程/进程数；结束时核对 10/10 存活与一次恢复 invoke。
- 插件运行时：Win11 用 Python NDJSON fixture；WSL **用 bash shell fixture**（不启 Python，按用户要求）。
- 客户端是 Python 线程（非 asyncio）；1000 worker 时客户端本身可能成为瓶颈，见「注意」。

## 解读

1. **显式 50 MB 现在真的按 50 MB 生效**：生效预算 52428800，不再是 64 MiB；形状 `tiny` 派生
   `max_connections=9` / `max_streams=8` / `max_subscriptions=4`。worst_case 41.2 MiB ≤ 50 MiB，
   所以能启动；再小就会按不变量拒绝启动。
2. **单并发**：50 MB 下 10 个 worker 已超过 9 条连接，成功率 Win 82% / WSL 76%；512 MiB 与 2 GiB
   都是 100%。p95 在 115–190 ms。
3. **每插件 50/100 并发**：50 MB 下预算只能接纳 9 条连接，成功率 Win 17%/11%、WSL 2.4%/1.5%，
   p95 0.7–2.2 s、p99 0.7–3.6 s；拒绝主要是 `429`（订阅）与 `503`（连接/流），另有大量
   accept 层 `ConnectionReset/Aborted`。daemon 全部存活，没有 5xx（除预期的 503）、没有重启/OOM。
4. **预算越大，接纳越多**：2 GiB `streaming` 给到 682 条连接 / 64 订阅，Windows c50 达到
   490 ops/s（本矩阵最高）；但 10 插件 × 100 并发 = 1000 条连接仍超过 682，且 `per_ip=64`
   先撞线，所以 c100 的成功率仍只有 6–12%。
5. **平台差异主要来自插件运行时**：WSL shell 插件让 spk RSS 从 Windows 的 ~182 MB 降到 ~33 MB，
   daemon RSS 从 12–18 MB 降到 5–6 MB，线程稳定在 4（reactor）；Windows 是每连接线程回退，
   daemon 线程随并发升到 39–117。
6. **客户端注意**：Windows `512mb-c100` 首轮只跑到 14.8 ops/s（1000 线程 + 连接拒绝的瞬时拥塞），
   同一格复跑为 183.7 ops/s；表里用的是复跑值。要测满 500/1000 连接，客户端应改 asyncio，
   并显式抬高 `max_connections_per_ip` / `max_connections`（否则测的是拒绝路径）。

## 复现

```sh
# Win11
python tools/perf/budget_scenario.py --budget 50mb --plugins 10 --duration 60 \
  --per-plugin-concurrency 100 --no-oversubscribe

# WSL2（shell 插件）
python3 tools/perf/budget_scenario.py --binary /path/to/linux/svcd \
  --work /tmp/svcd-matrix --budget 50mb --plugins 10 --duration 60 \
  --per-plugin-concurrency 100 --no-oversubscribe
```
