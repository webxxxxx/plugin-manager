# 20 插件 × 50 WebSocket：512 KiB JSON echo 压测

日期：2026-11-16  
平台：WSL2 Debian Linux x86_64  
构建：`cargo build --release`，默认 `MEM_LEVEL=high`  
连接：20 个 WebUI 插件，每个 50 条 WebSocket，共 **1000 条**  
消息：每条 WS 发送一条约 **512 KiB** 的 JSON-RPC `tools/call`，插件原样返回 `data`

## 配置

```text
max_connections = 4096
max_connections_per_ip = 4096
max_streams = 4096
max_subscriptions = 2048
max_subscribers_per_plugin = 64
http_idle_timeout_secs = 300
```

20 个插件都声明了 `echo` capability，payload 是 Python NDJSON agent：

```json
{"jsonrpc":"2.0","id":1,"method":"tools/call",
 "params":{"name":"echo","arguments":{"data":"<512 KiB string>"}}}
```

插件返回：

```json
{"jsonrpc":"2.0","id":1,"result":{"data":"<原样返回>"}}
```

检查结果：

- 1000 条请求全部完成；
- `data_ok = 1000`，即 1000 条返回的 `data` 都与发送值完全一致；
- 客户端 `errors = 0`；

- daemon stderr / `svcd.log` 没有 `panic`、`overflow`、`fatal`、`abort`、`too large`、`reset`。

## 解读

- 500 MiB 请求在约 1 秒内全部发完，随后服务端逐一处理并回传 500 MiB。
- 请求 payload 吞吐约 **50.26 MB/s**，约 **421.6 Mbit/s**；
  双向合计约 **100 MB/s**。
- 1000 条并发 512 KiB 请求的端到端延迟：
  - 最小 **1.51 秒**
  - 平均 **5.81 秒**
  - 最大 **9.95 秒**
- daemon RSS 约 **996 MB**，峰值 **1.1 GB**，总 RSS 约 **1.22 GB**；
  这是 1000 条连接同时持有 512 KiB 请求/响应缓冲的代价，明显不适合 50 MB 设备。
- daemon 线程仍为 **10**，不会因为 1000 条连接或 512 KiB 消息而增加线程。
- daemon CPU 约 **2.57 个核**，插件进程 CPU 约 **31%**（20 个 Python agent 合计）。
- 本次是**一轮** 1000 × 512 KiB 的 echo，不是无限连续发送；如果要持续 1 分钟，
  需要增加轮次，内存和延迟会进一步累积。
